# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns 200 unconditionally without verifying MongoDB connectivity. | MongoDB daemon stopped; `GET /health` still responds with 200 OK instead of 503. | Added `db.command("ping")` inside a try/except block; raises HTTP 503 if the database is unreachable. |
| 2 | Startup / Lifespan | No indexes are created at startup. | Simultaneous duplicate inserts succeed; listing 100k records performs slow `COLLSCAN`. | Added a FastAPI `lifespan` context manager that idempotently creates unique and compound indexes on startup. |
| 3 | `EmployeeIn` (lines 53-60) | Lacks input validations specified in the OpenAPI contract. | Posting `emp_code="123"` or identical `shift_start`/`shift_end` is accepted with 201. | Added regex for `emp_code` (`^EMP\d{4,6}$`), email pattern, 24-hr time formats, and a validator ensuring `shift_start != shift_end`. |
| 4 | `PunchInIn` (line 65) | `punched_at: Optional[int]` allows Pydantic to coerce strings and floats into integers. | Posting `punched_at="1783312500000"` or `1783398900000.0` succeeds with 201 instead of returning 422. | Replaced with `StrictInt` via `Annotated[StrictInt, Field(ge=MIN_EPOCH_MS, le=MAX_EPOCH_MS)]` to reject non-integers with 422. |
| 5 | `create_employee` (lines 78-85) | TOCTOU race condition using `find_one` before `insert_one`. | Two concurrent POSTs with the same `emp_code` both pass the check and attempt insertion. | Enforced by a MongoDB unique index on `emp_code`; caught driver `DuplicateKeyError` and returned HTTP 409. |
| 6 | `create_employee` (line 82) | Sets `created_at` as a naive local datetime and leaks it in the response. | Response returns ISO datetime string instead of epoch milliseconds required by OpenAPI. | Store UTC datetime in MongoDB; convert to integer epoch milliseconds in the API response. |
| 7 | `list_employees` (line 93) | Pagination skip formula is `skip = page * page_size`. | On `page=1`, the first 20 records are skipped, displaying items 21-40. | Corrected the formula to `skip = (page - 1) * page_size`. |
| 8 | `list_employees` (line 94) | `total` count ignores the active department filter. | Filtering by `department=Engineering` still returns total collection count. | Passed the filter query dictionary `query` into `db.employees.count_documents(query)`. |
| 9 | `list_employees` (line 95) | Missing sort order on cursor. | Employees are returned in arbitrary insertion order. | Added `.sort("emp_code", ASCENDING)` to guarantee deterministic ascending sorting. |
| 10 | `compute_late_minutes` (lines 33-37) | Inverts grace threshold and ignores timezone / overnight shifts. | At 09:40:01 (601s), `int(601/60)=10`; `10 > 10` is False, returning 0 instead of 10. | Evaluated `diff_seconds > 600`; floored elapsed minutes from shift start; aligned IST shift times with R1 overnight logic. |
| 11 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies banker's rounding (half-to-even). | 9.085 hours rounds to 9.08 instead of 9.09 per R4 half-up rounding. | Used Python's `Decimal` with explicit `ROUND_HALF_UP` rounding to two decimal places. |
| 12 | `compute_overtime` (lines 44-48) | Naive timezone comparison, returns overtime < 30m, and breaks across midnight. | Comparing naive vs aware datetimes raises `TypeError`; punch-out 10m late returns 10 instead of 0. | Verified `diff_seconds >= 1800` (30 mins); added calendar day offset for overnight shifts (`shift_end <= shift_start`). |
| 13 | `punch_in` (line 101) | Unhandled missing employee lookup raises 500. | Punch-in for non-existent `emp_code` throws `TypeError: 'NoneType' object is not subscriptable`. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 14 | `punch_in` (lines 104-105) | Check-then-insert race condition on `(emp_code, date)`. | Two concurrent punch-ins for the same day both insert duplicate records. | Created a compound unique index on `(emp_code, date)` and handled `DuplicateKeyError` with HTTP 409. |
| 15 | `punch_in` (lines 102-103) | Computes attendance date from machine local time ignoring IST and overnight shifts. | Overnight shift punch-in at 01:00 IST is assigned to the current day instead of previous shift date. | Implemented `determine_attendance_date` converting to IST and checking R1 overnight shift boundaries. |
| 16 | `punch_in` (line 119) & `list_attendance` (line 149) | Injects synthetic `id` attribute into attendance responses. | Responses contain `"id": "..."`, violating OpenAPI contract and leaking internal identifiers. | Removed `id` field generation and stripped MongoDB `_id` before returning responses. |
| 17 | `list_attendance` (lines 144-147) | Loads entire collection into Python memory (`list(db.attendance_logs.find(q))`). | Collection of 100k documents causes high memory usage and latency. | Pushed sorting (`[("date", -1), ("emp_code", 1)]`), `skip`, and `limit` directly to the database cursor. |
| 18 | `list_attendance` (lines 137-141) | Missing validation for inverted date filters. | Calling `?date_from=2026-07-31&date_to=2026-07-01` returns 200 with empty list instead of 422. | Added validation `if date_from > date_to: raise HTTPException(422)`. |
| 19 | Response serialization (lines 82, 110) | Datetime objects returned raw rather than converted to epoch milliseconds. | Client receives ISO strings or BSON datetime dicts instead of integer milliseconds. | Implemented boundary serializers (`serialize_employee`, `serialize_attendance`) mapping all BSON dates to integer epoch ms. |

### Examined and decided was NOT a defect
- **`dotenv` local loading**: `load_dotenv()` at top of `app/main.py`. This is standard for local convenience; since `os.getenv` reads existing environment variables first, real injected environment variables take precedence as required.
- **`status` default value in `PunchInIn`**: Defaulting `status` to `"PRESENT"` when omitted matches the OpenAPI specification default.
